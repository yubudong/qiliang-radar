# 起量雷达使用说明

版本：v0.1.6 ｜ 文档更新：2026-10-01

起量雷达用于观察 Temu 竞品店铺商品的**显示销量增量**，帮助发现近期开始增长的商品。它是运行在 Tampermonkey（油猴）中的用户脚本，不是独立的 Chrome 扩展。


## 适用人群与解决的问题

起量雷达适合 Temu 店铺运营、选品人员、个人卖家及小团队。它帮助减少每天逐个查看竞品的工作，把零散观察变成连续记录，区分累计销量高的成熟商品与最近正在加速增长的候选商品。

每天先按参考增量观察增长较大的商品，再结合连续增长和增速变化筛选“新星”，最后人工核对款式、价格和供应能力。它辅助选品判断，不承诺预测爆款。

## 一、先了解它能做什么

- 在店铺商品列表读取页面展示的累计销量。
- 点击“开始”后自动滚动、点击店铺的“查看更多”，加载后续商品。
- 按最低累计销量门槛筛选，默认 20 件，可调整。
- 在当前浏览器本地保存每日记录，比较昨日和今日。
- 展示近 3 日平均增量、连续增长天数、增速变化、首次发现日期，并提供“新星”筛选。
- 导出带店铺名和日期的 CSV。

**每天需要自己打开店铺并点击“开始”。** 浏览器关闭、电脑休眠时不会继续采集，也没有定时后台监控。

当前面向桌面 Chrome、Temu 美国站、简体中文店铺页。其他浏览器、国家站、语言和手机端未完成适配验证。Temu 页面变化、登录或验证、网络问题都可能影响采集，不能保证所有店铺始终采全。

## 三、首次安装

### 1. 安装 Tampermonkey

1. 使用电脑上的 Chrome。
2. 打开 [Tampermonkey 官方网站](https://www.tampermonkey.net/)，通过官网的 Chrome 入口进入官方扩展商店。
3. 安装 Tampermonkey，阅读浏览器显示的权限提示。
4. 点击 Chrome 右上角拼图图标，将 Tampermonkey 固定到工具栏，便于操作。

### 2. 开启“允许用户脚本”

1. 在 Chrome 地址栏输入 `chrome://extensions/`。
2. 找到 Tampermonkey，点击“详情”。
3. 找到并开启“允许用户脚本”（Allow User Scripts）。
4. 确认 Tampermonkey 本身处于启用状态。

新版 Chrome 通常提供此开关；不同版本入口可能不同。若没有该选项，请参考 [Tampermonkey 官方权限说明](https://www.tampermonkey.net/faq.php?locale=en&q=Q209)，不要通过反复卸载扩展排查。

### 3. 安装起量雷达脚本

推荐采用复制粘贴方式，不需要开启“允许访问文件网址”。

1. 解压 ZIP。
2. 用文本编辑器打开 `qiliang-radar.user.js`，例如 VS Code、Windows 记事本或 Mac 文本编辑。
3. 全选并复制文件中的**全部内容**，包括最上面的 `// ==UserScript==` 信息。
4. 点击 Tampermonkey 图标 → “添加新脚本”。
5. 删除编辑器中的默认示例代码，将复制的全部内容粘贴进去。
6. 保存：Mac 按 `⌘S`，Windows 按 `Ctrl+S`。
7. 在 Tampermonkey 管理面板确认出现“起量雷达”，版本为 `0.1.6`，开关已开启。

不要把代码粘贴到网页控制台，也不需要把 ZIP 拖入 Chrome 扩展管理页。

### 4. 打开支持的店铺页面

1. 打开 [Temu](https://www.temu.com/)。
2. 将国家/地区切换为美国，语言切换为简体中文。
3. 如果页面要求登录或验证，由自己正常完成。
4. 进入目标店铺的“商品”页，网址通常包含 `mall.html?mall_id=...`。
5. 刷新页面，右上方应出现“起量雷达”面板。
6. 核对面板上的店铺名称和 `US` 标识。

只打开商品详情、搜索结果或首页，不会显示店铺采集面板。脚本不会自动进入详情页核实万件以上的精确销量。

## 四、第一次采集

1. 确认目标店铺，尽量使用“商品”下的完整列表，清除不需要的分类或搜索筛选。
2. 设置“最低累计销量”。默认 `20` 表示只保存显示累计销量达到 20 的商品，**不是最多采集 20 个商品**。
3. 点击“开始”。不需要先手动点“查看更多”。
4. 保持店铺页打开、电脑唤醒。采集中不要切换店铺、排序或分类，也不要同时启动另一个店铺批次。
5. 观察统计栏，等待结束。大店铺需要更多加载时间。
6. 确认是否采全；如果显示“本次结束（未采全）”，只代表本轮停止，不代表全店完成。
7. 导出 CSV 留底。首次采集通常显示“新收录”，没有昨日增量是正常情况。

门槛修改从下一批次生效。同一天再采集会更新当天记录，不会产生额外的一天，也不会将两次累计销量相加。

## 五、统计栏怎么看

| 项目 | 含义 |
|---|---|
| 已扫描 / 店铺总商品数 | 本轮已识别的不同商品数 / 页面报告总数；分母无法读取时显示“未知” |
| 保存成功 | 本轮符合门槛且已保存列表记录的商品数 |
| 低于门槛跳过 | 已读到销量，但低于设定门槛 |
| 未展示销量 | 未读到销量标签，单独列出，不记为零 |
| 失败商品 | 尚未被成功读取或低门槛结果覆盖的异常商品，按商品去重 |
| 运行异常 | 无法归属到某件商品的运行问题，例如存储异常 |

采集中统计会变化。历史表格可能显示之前保存的商品，因此**表格行数不一定等于本次保存成功数**。刷新后的表格记录也不能单独证明上一轮是否采全。

例如：已扫描 744 / 744，保存成功 133，低于门槛跳过 271，未展示销量 340，失败商品 0。这表示 340 件商品没有展示销量，不代表 340 件采集失败，也不证明它们销量为零。

## 六、每天怎样使用

建议每天在相近时间采集，保持同一浏览器资料、国家站和语言。

1. 打开目标店铺并刷新。
2. 核对店铺、门槛，点击“开始”。
3. 等待采集完成，检查统计和完整性。
4. 查看增量较高商品，再使用“新星”筛选。
5. 导出当天 CSV。
6. 第一个店铺结束后再采集下一个店铺。

日期按**北京时间自然日**划分，不按美国当地日期。日期选择器用于查看、导出历史日期，不能把今天采到的数据补写成昨天。缺一天不会自动补采，也不会用前天冒充昨天。

## 七、表格指标与新星筛选

| 指标 | 定义与使用方式 |
|---|---|
| 昨日参考 / 今日参考 | 同一商品对应自然日的可比较显示销量；首次记录或不可比较时可能为空 |
| 参考增量 | 今日显示累计销量减昨日显示累计销量；默认按可计算增量降序展示 |
| 近 3 日均增量 | 今日、昨日、前日三个日增量的平均值；需要连续 4 天有效记录 |
| 连续增长天数 | 截至所选日期，连续日增量为正的天数；遇到零、下降或缺采停止。若历史边界未知，显示“至少 N” |
| 增速变化 | 今日增量减此前 3 日平均增量；需要连续 5 天有效记录，正数表示今日比此前平均增长更多 |
| 首次发现 | 当前本地记录中第一次收录日期，**不是平台上架日期** |
| 状态 | 新收录、缺少昨日记录、今日未采到、需复核等 |

近 3 日均增量和增速变化以“约”显示，保留至多一位小数。缺采、不可比或下降导致所需窗口无效时显示“数据不足”，不补零、不拼接不连续日期。

例：连续五天累计销量为 20、22、26、32、42，日增量分别为 2、4、6、10。

- 近 3 日均增量 = (4 + 6 + 10) / 3 ≈ 6.7。
- 增速变化 = 10 − (2 + 4 + 6) / 3 = 6。
- 连续增长至少 4 天；更早情况未知。

“新星”需同时满足：

1. 首次发现至所选日期少于 7 天，即含首次发现当天的 7 个自然日。
2. 连续增长至少 2 天。
3. 增速变化大于零。

新星只是观察候选，不是爆款预测。刚安装时历史不足，新星筛选为空很正常。已有老商品也可能因为首次被记录而进入新星，需结合款式、价格等人工判断。

筛选菜单：全部、新星、新收录、需复核。点击状态旁的小三角可查看来源原文和采集时间等信息。表格较宽时可横向滚动，点击“折叠”可收起内容。

## 八、导出 CSV

1. 选择要查看的日期。
2. 选择筛选项；若要导出全部结果，先选择“全部”。
3. 点击“导出 CSV”。
4. 文件名示例：`起量雷达-HAPPY THREADS-2026-09-12.csv`。

CSV 导出**当前日期、当前筛选下的表格结果**，包括新增趋势指标。它不是完整的运行日志，不包含所有跳过或失败商品的逐项明细。

可用 Excel、WPS 等打开；中文乱码时通过“从文本/CSV 导入”选择 UTF-8。商品 ID 为长数字，应按文本处理，避免表格软件转换成科学计数法或损失精度。

## 九、按钮与暂停

- **开始**：以当前门槛启动本轮采集。
- **暂停**：暂时停止；页面或存储问题可能也会导致暂停。
- **继续**：恢复暂停的批次；不会凭空补齐未加载的数据。
- **结束本次**：停止后续操作，保留已经保存的记录。
- **跳过当前**：为旧详情任务保留的按钮；当前列表采集版通常不需要使用。
- **导出 CSV**：导出当前日期及筛选结果。

如果出现登录或验证，自己正常处理后再尝试继续。没有恢复时，结束本次、刷新店铺再开始。不要持续快速反复点击按钮。

## 十、数据保存、更新与分享

数据保存在当前 Chrome 浏览器资料中该脚本的 Tampermonkey 存储里。起量雷达不提供云同步；朋友安装后从自己的第一天开始积累，不会获得你的历史数据。

更新方法：编辑现有“起量雷达”，全选替换新版代码并保存，然后刷新店铺。不要先删除旧脚本；保持同一个脚本条目更新，有利于保留原有记录。

更换电脑、浏览器资料、清除扩展数据或删除脚本前，先导出需要的 CSV。**当前不支持把 CSV 导入恢复为插件历史记录。** 仅复制 `.user.js` 文件不是数据备份。

把本 ZIP 发给朋友即可；不需要分享自己的浏览器资料、登录状态或采集 CSV。

## 十一、常见问题

### 看不到面板

依次检查 Tampermonkey 已启用、“允许用户脚本”已开启、起量雷达已保存且启用、当前是美国站简体中文店铺页。直接刷新店铺再试。网站异步加载或结构变化仍可能导致启动失败；记录版本、店铺链接和截图反馈，不要反复卸载重装。

### 采集数量比店铺商品总数少

先区分“已扫描”和“保存成功”。低于门槛及未展示销量的商品不会成为成功记录；若已扫描仍明显少于总数，或者显示未采全，则是加载未完成。脚本有等待和轮数上限，不会无限请求；排除页面验证或网络问题后再重试。

### 页面不显示销量，是否为零

不能确定。仅记录“未展示销量”，不按零处理。以后显示并达到门槛时才收录。

### 今日没有增量、趋势都是数据不足

首次采集、昨日缺采、近几天缺失或口径不可比都会如此。先连续采集几天，不要修改电脑时间制造历史。

### 为什么有“约”、负数或不能相减

“1.1万”等展示值已经被平台取整，差值只能是粗略参考；“1万+”属于下界，不计算精确差值。显示销量下降需要复核，不能直接解释为退货。数据可能延迟或集中更新，**显示销量增量不等于真实日订单，更不是严格24小时销量**。

### 刷新后统计不见了，但表格还在

表格读取的是已保存的每日记录，统计栏表示本次运行状态。当前版本不把上一轮完整统计作为历史报表展示；需要时在结束后截图留底。

### 反馈问题需要什么

提供脚本版本、店铺链接、美国站/语言、操作步骤、统计栏截图以及是否有登录或验证提示。无需发送密码、验证码或浏览器账号资料。
